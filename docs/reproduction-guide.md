# Agent 高保真重建与复用规约

目标是从用户给出的图和材料，做出可核对、可运行、可修改的实现。优先保持科学含义和视觉结构，再校准样式细节。没有材料支持的信息保留未知；合理实现选择直接完成并记录，不需要逐项向用户确认。

本规约同时适用于用户自制图、论文图、网页截图和附有代码的图。只有用户明确要求选图时才查目录；点名 ID 时只读取该条目。

## 1. 接收材料，确定重建范围

先查看实际图片、已有文件和用户要求。确认目标是整张多面板图、一个子图，还是某些指定样式；用户没有限定时，按提供图像的完整范围处理。优先使用用户实际提供的高分辨率图、矢量原件和配套代码，避免从已经压缩的缩略图开始推断。

新条目的操作形态为：

```bash
python scripts/figurelib.py new my-reference --title "图的简短名称" --reference /absolute/path/figure.png --source-kind paper
```

额外材料可以用重复的 `--asset /absolute/path/file` 导入。它接受文件；多文件代码可以逐项导入，或将完整来源工程作为材料另行检查。来源代码被保存为参考，不会因导入而自动运行。

保留原件及其哈希；裁切、透明背景处理和渲染版本保存为派生文件。PDF、SVG 可以作为来源材料保留，`assets.reference` 则指向用于视觉对照的栅格图。该栅格视图也要登记在 `source.files` 中并记录 SHA-256，同时说明生成方法。只截取某个子图时，记录原页码、图号和裁切范围，防止把相邻面板的图例误用过来。

链接、DOI、图注缺失不阻止收集，也不能用猜测补齐。来源的实际代码与目标图是否对应，要通过参数、标签、数据和渲染核对。

## 2. 先判断数据与科学信息能恢复到什么程度

在 `figure.yaml` 中设置 `data.kind`，并写明依据：

| 取值 | 使用条件与记录要求 |
| --- | --- |
| `original` | 实际获得用于该图的数据或可信的提供数据；说明原始观测、汇总值或分析输出的具体性质 |
| `digitized` | 从参考图估计坐标或图示数值；记录坐标标定、提取范围及已知误差 |
| `synthetic` | 没有足够数值，使用模拟或手工演示输入复原风格；说明它不代表来源研究结果 |
| `unknown` | 目前不能确定数据来源与性质；保留未解决事项 |

逐项核对图上可见的单位、轴尺度、基线、组别、类别顺序、区间、样本量、图例和注释。统计方法只能从明确材料确认：外观上的误差线不能自动解释为 95% CI，阴影不能自动解释为标准差，星号也不能自行补上检验方法。

截图数字化需要先确认是线性轴、对数轴还是离散类别。用已知刻度标定像素坐标；对数轴在对数空间插值。分别提取点估计与上下界，保留近似性质。不要从生存曲线直接编造个体生存时间，不要从箱线图或小提琴轮廓声称恢复了原始分布。图像分辨率不足时，降低数字化精度并写明限制。

重建模拟图时可以保留原图的结构关系，但不能伪造来源文章的实际 P 值、样本量或结论。对模拟或提取数据的“数据检查通过”，表示性质已明确、输入输出一致，不表示原始科学结果已经重现。

## 3. 拆解布局，再校准视觉参数

先记录画布长宽比、面板数量与相对位置，再看每个面板的内容。多面板图需要区分外层画布留白、面板之间的间距、绘图区内部边距和图例占位；仅调整整体 `tight_layout` 很难准确重建这些关系。

重点检查以下内容：

- 面板比例、共享坐标、跨面板对齐，标题和 A/B/C 标签的锚点。
- 刻度位置、轴范围、变换、基线、网格密度，以及图内和图外注释。
- 图例排序与图形排序是否相同，颜色是否在多面板间保持语义一致。
- 线宽、点大小、误差线端帽、透明度、带状区域与文字的前后层次。
- 颜色、线型、点型共同表达的类别，以及最终尺寸下的辨识度。

尺寸写清单位：`figure.width_mm` 和 `height_mm` 表示物理尺寸，字体以 pt 记录，`dpi` 控制栅格导出分辨率。截图像素尺寸可以支持长宽比，不能独自证明原图的毫米尺寸。未知物理尺寸时选定适合目标用途的值，并在 `review.provenance` 记为实现选择。

优先从对应源码确认配色、字体和参数；只有图片时，从线条内部或色块内部取色，注意抗锯齿、压缩和半透明叠色。不要把背景混合后的像素颜色误记为原始线条颜色与 alpha 的唯一组合。

字体先核对实际可用性，再设置并查看导出结果。无法获得原字体时，选择字形、粗细、宽度接近的替代字体，记录替代原因；检查中文、希腊字母、数学符号和负号。不得在未核验字体的情况下宣称与来源完全一致。

## 4. 写成真正可修改的实现

`style.yaml` 保存代码实际读取的设置。稳定的颜色角色、字号层级、面板参数、轴范围和图例选项应尽量集中；与特定图形有关的字段可自然扩展。来源观察与不确定性写入 `review.provenance`，不要把推测包装成作者真实参数。

数据契约至少写出列名、类型、必需性和含义，再把关键约束落到绘图代码中。例如上下界包含点估计、对数轴数值必须为正、语义类别不能重复或缺失、单位必须统一。发现输入不符合条件时给出明确错误，不静默删除行、不截断异常值、不擅自把缺失换成零。

Python 配方应能从条目目录独立执行：

```bash
python code/plot.py --data data/example.csv --style style.yaml --out rendered
```

它读取实际数据和配置，输出 `figure.png`、`figure.svg`、`figure.pdf`，并提供 `--help`。如需随机数据，固定种子并说明生成方式。依赖版本依据实际验证环境填写，不编造“已测试”版本；不要依赖本机绝对路径、工作目录之外的隐藏文件或仓库管理器内部模块。

管理器支持显式调用 Python，以及存在 `Rscript` 时调用 R 入口。R 条目采用相同的数据、样式、参数和输出约定，并自行声明 R 包依赖；本包的演示和运行证据验证使用 Python，不能据此声称 R 配方已验证。当前环境不能运行某语言时保留待运行状态，报告实际限制。

不使用把参考图整张嵌入画布的方式冒充重建。确需使用不可重画的照片或组织切片面板时，将该部分明确标成外部图像素材，区分可参数化绘制和原图保留部分。

## 5. 渲染与对照

完成源码检查与依赖准备后，运行指定条目：

```bash
python scripts/figurelib.py render my-reference
python scripts/figurelib.py compare my-reference
```

`render` 通过明确入口执行，记录有关输入与输出摘要，失败不应毁掉旧成果。管理器没有自动安装、联网下载、提交或推送行为。来源代码若包含其他任务，先提取真正需要的绘图部分，再作为本条目的实现运行。

`compare` 生成保持长宽比的对照图。实际查看参考图、输出和对照，不凭终端“运行成功”判断还原质量。先看最终使用尺寸，再看局部细节。对比差异图或叠加图只是定位工具，不能把单一像素指标转成通用准确率。

多面板对照先核对整体比例，再逐面板检查，最后确认公共图例、共享坐标和跨面板注释。对 PDF/SVG 也要验证关键文字和布局：PNG 正常不自动证明其他格式完全正常。

## 6. 三类验收独立进行

### 视觉检查

检查面板比例、图形位置、配色关系、字体层级、线点样式、图例、边距、裁切和遮挡。将仍然存在的差异写入 `known_differences`，区分影响理解的差异和有限分辨率下的细微差异。`visual_checked` 必须基于实际查看的输出。

### 数据与科学检查

对照输入确认点值、上下界、分组和顺序，检查轴尺度与单位，确认注释对应实际信息。核对代码没有为了图形相似而篡改数值，模拟数据标记没有丢失，无法确认的统计算法没有被补写为事实。将检查对象与结论写入 `checks`，再设置 `data_checked`。

### 新输入复用检查

另用一份实际不同的数据运行，使用独立目录：

```bash
python scripts/figurelib.py render my-reference --data /absolute/path/changed.csv --out /absolute/path/variant-output
```

依据条目用途改变数值、标签、类别数量或范围，不必测试与适用范围无关的所有情况。查看新图，确认参数确实生效，颜色和类别没有错配，较长标签或变化的数值没有引起裁切。若配方只支持固定面板数量，明确写入复用限制。

保存该次真实 `run.json` 到条目内 `review/evidence/changed-input-run.json`，并增加结构化记录：

```yaml
checks:
  - kind: changed-input
    summary: 写明实际改变的输入以及查看新图后的具体结论
    run: review/evidence/changed-input-run.json
```

这里需要真实证据，不能手工编造一份运行记录。只有改了文件名但数据摘要相同，不构成改变输入；沿用旧代码产生的运行证据也不能证明当前实现可复用。此项完成后再设置 `reuse_checked`。

## 7. 绑定当前运行，提交条目状态

`reviewed_run` 设为实际检查过的主 `outputs/run.json` 的 SHA-256，并填写检查者、具体总结、检查项、剩余差异与信息依据。视觉与数据检查完成后可设 `reproduced`；有有效新输入证据及复用结论时才设 `reusable`。随后执行：

```bash
python scripts/figurelib.py validate my-reference
python scripts/figurelib.py build
```

主运行与新数据运行是两个记录：`reviewed_run` 绑定基线，结构化 `changed-input` 检查绑定变体。重新渲染基线，或修改实现、样式、数据、契约、参考图、来源信息、数据性质与说明、执行入口及依赖清单后，重新核对对应证据。不要为了绕过失效检查，只更新哈希而不再查看实际输出；需要复用时也重新验证受改动影响的新输入情形。

## 8. 迭代优先级与停止条件

修正顺序是：科学含义与数值对应 → 主要布局和视觉编码 → 文字可读性与输出完整性 → 配色、线宽和间距细节。只迭代实际观察到的问题，不设置无限轮次或强制达到某个相似度百分比。

当关键含义保持一致、主要结构和样式达到材料允许的还原程度、输出可读且不缺失、运行与验收证据有效，就可以完成。仍有微小字体差异、来源尺寸未知或截图数字化误差时，清楚列出，不需要一直等待用户裁决。缺少足以决定科学含义的信息时，保留相应边界；其他已授权部分继续完成。

最后向用户返回 ID、重建图与对照、数据性质、主要剩余差异，以及以后怎样点名复用。一次自生成示例成功，只证明该例的工程链条运行正常，不能据此报告对陌生论文的普遍复现准确率。完成入库本身不包含自动提交、推送或建站。

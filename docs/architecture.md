# 仓库架构与设计取舍

这个仓库保存的是一张图的完整绘制方法：参考材料、实际实现、配色与布局、输入要求、重建结果，以及证明它能够运行和复用的记录。你决定何时使用图库、使用哪个条目；Agent 只在收到指令后处理指定图。

## 1. 从旧版保留什么，调整什么

旧版的主要能力是保存图片资料卡、记录偏好、检索参考和构建网页。`scripts/figurelib.py` 的导入流程会复制图片和源码，但没有要求源码真正生成该图，也没有记录新数据运行结果。“有代码”与“可复用”因此是两件尚未连接的事。

这次保留稳定 ID、来源记录、结构校验、原件保留和未知信息显式标注。工程重心放到单图重建与复用上：

| 旧版设计 | 本版处理 |
| --- | --- |
| 图片、来源、配色和科学任务的资料卡 | 扩展为完整条目，加入可运行实现、数据契约与验收记录 |
| 图片观察的 provenance | 区分确认信息、推断信息、实现选择及未知信息 |
| Skill 安装、自动触发、绘图前全库检索 | 绘图侧移除，仍按 ID 手动复用；v0.4.0 起只保留一个收录用 skill（`figure-collect`），在用户明确要求收图时走固定流程并推送 |
| 全局偏好记忆、七维评分和推荐权重 | 简化为逐图 `why_saved`、复用范围和注意事项 |
| 网页与自动发布脚本 | 先生成稳定的目录数据；v0.3.0 起由 `site` 命令生成静态网页，Pages 只部署显式选入的内容 |
| 存入图库默认提交和推送 | 移除；本地管理命令没有 Git 或网络副作用 |

对上传旧包的检查没有发现真实收藏条目，只有空图库和模板。因此本版可以直接采用新的字段结构，没有遗失需要迁移的图。新的演示案例均单独放在 `examples/`，不会变成你的收藏。

## 2. 两条日常工作流

### 收藏并重建一张图

你提供图片，附带代码、数据、图注或来源链接中的任意一项。Agent 先保留原件，再确认哪些信息能够从材料中获得，完成重建、查看实际输出、测试复用，最后更新条目和目录。

只有截图也能开始；未知信息不阻止收集。缺少原始数据时，条目可以使用明确标记的模拟数据演示图形结构，但需要如实说明数值没有被恢复。模拟数据图可以成为可复用的绘图配方，其数据性质始终保持 `synthetic`。

### 指定一个条目给新项目作图

你提供 ID，以及希望沿用的方面，例如“用 `forest-ci` 的配色和置信区间样式”。Agent 读取该条目的说明、图像、样式、数据契约和实现，将新数据映射到契约，再输出新图。新项目结果使用独立输出目录；经典参考和已经验收的基线不被覆盖。

命令入口对应如下：

```bash
python scripts/figurelib.py context forest-ci
python scripts/figurelib.py show forest-ci
python scripts/figurelib.py validate forest-ci
python scripts/figurelib.py bundle forest-ci --out ../forest-ci-copy
```

`bundle` 导出可独立运行的完整条目与 `AGENT_BRIEF.md`，适合交给另一个研究项目。包中也包含参考材料，需要按这些材料本身的公开范围使用。

## 3. 一个条目的文件职责

正式收藏放在 `figures/<id>/`，演示案例放在 `examples/<id>/`。ID 不随标题修改而改变，目录名与清单中的 ID 必须一致。

| 文件或目录 | 权威内容与用途 |
| --- | --- |
| `figure.yaml` | 条目身份、来源、数据性质、状态，以及其他文件的相对路径 |
| `reference/` | 原图、图注和来源代码等原始材料，导入后按 SHA-256 检查完整性 |
| `style.yaml` | 本次实现实际读取的颜色、尺寸、字体、布局和图形参数 |
| `code/plot.py` 或 R 入口 | 把输入数据与样式变成图形的实现 |
| `code/requirements.txt` | 当前 Python 配方运行所需依赖；记录实际验证过的版本 |
| `data/contract.yaml` | 列名、类型、语义和约束；具体数值校验由绘图代码落实 |
| `data/example.csv` | 随配方提供的输入，数据性质由清单明确说明 |
| `review.yaml` | 实际检查、差异、信息依据及验收绑定 |
| `outputs/` | 图像、缩略图、对照图与运行记录，均由上述输入派生 |
| `README.md` | 面向人的简短使用说明、适用情形和已知限制 |

这里的“权威”是指维护位置唯一，不代表材料天然正确。原件哈希能发现文件改变，无法证明一份来源代码对应论文最终图，也无法证明论文统计结论正确。

## 4. 三类信息分开维护

### 原材料中的事实

数据、图注与经核对的来源代码支撑科学含义。样本量、单位、变换、置信区间定义和模型选择，需要具体材料支持。图片能够显示一条区间线，却通常不能证明这条线通过哪种算法计算。

`data.kind` 区分 `original`、`digitized`、`synthetic` 和 `unknown`。原始或实际提供的数据、从图片提取的近似值、演示数据不能互相替代。`data.notes` 写清来源与边界，图像目录也展示数据性质。

### 实现实际采用的设置

`style.yaml` 写实际运行值。例如参考图字体不能确定，但实现选择了已安装字体；样式里记录所用字体，`review.provenance` 说明它属于 `choice`。观察到的近似颜色可以标为 `inferred`，从对应代码确认的设置可以标为 `verified`，没有依据的内容保留 `unknown`。

一个配置项只有被代码读取并影响输出，才具有复用价值。配色应该关联语义角色，面板位置应该能调整，数据列应该有明确解释。大量看似专业、实际没有被代码使用的字段只会增加维护负担。

### 运行与检查证据

`outputs/run.json` 记录执行参数、有关输入及输出的摘要、运行环境等信息。`reviewed_run` 保存被检查的主运行记录的 SHA-256；代码、样式、输入或结果改变后，旧记录不能继续证明当前图已经验收。

`review.yaml` 中的视觉、数据和复用检查分别成立，不合并成一个“还原准确率”。可复用状态还需要实际改变输入后的运行证据。结构化检查项引用 `review/evidence/changed-input-run.json`，并说明测试了什么变化；校验器会核对新数据摘要确实不同，以及证据与当前实现的对应关系。

## 5. 状态表示完成程度，数据性质表示证据边界

| 状态 | 含义 |
| --- | --- |
| `captured` | 原材料已保存，尚未形成完整实现 |
| `draft` | 正在实现或调整；可能已有运行产物，但尚未完成验收 |
| `reproduced` | 当前主运行已通过视觉与数据性质检查，差异已记录 |
| `reusable` | 在上述基础上，另有实际改变输入的运行证据和复用结论 |

状态不会抹去来源限制。`reproduced + synthetic` 表示模拟数据条件下的视觉重建经过检查，不表示恢复了论文真实数值。`reusable` 也只适用于条目中声明的数据形态和复用范围，无法保证任意数据都会得到合理图形。

Agent 可以在实际检查后填写验收，不需要为每个字段请求你的确认。运行成功不会自动把状态提升为已验收；有意义的差异和检查内容仍需要判断。

## 6. 按需读取与独立运行

`show`、`context`、`render` 和指定 ID 的 `validate` 直接定位目标目录，不遍历全库。只有 `list`、全库校验、`build` 等明确的全局操作才枚举条目。常规阅读顺序是简短上下文、清单与说明、目标图片和配置、需要修改的代码；原论文和完整历史只在当前问题需要时读取。

绘图脚本不导入仓库管理器，只依赖同条目的文件和声明的运行环境。Python 入口遵循：

```bash
python code/plot.py --data data/example.csv --style style.yaml --out rendered
```

管理器可以显式调用 Python 或已安装的 `Rscript`，不会自动安装语言和依赖，也不会因为文件被导入就执行它。当前可运行演示和完整流程验证使用 Python；R 可以沿用相同的数据、样式、输出和验收约定，但需要可用的 R 环境及条目自己的依赖说明。本版不提供 Python/R 自动转换。

主输出先在临时位置生成，成功后再替换基线；失败不应损坏上次成果。传入外部数据或样式时必须指定独立 `--out`，以保留已经收录的版本。

## 7. 网页读取什么

`build` 生成 `catalog/catalog.json` 和 `catalog/GALLERY.md`。目录包含稳定 ID、标题、标签、图类型、状态、数据性质、配色摘要与相对资源路径；详情依靠 ID 对应的条目文件加载。前端可以先载入轻量卡片，再按需读取某张图，无需把所有代码、原件和历史塞进首页。

默认目录只包含真实收藏，演示需显式使用 `--include-examples`。目录是派生数据，不能手改成第二份清单；修改权威文件后重新构建即可。

将来制作公开页面时，`export-public` 只导出明确加入公开目录、写明权利说明的预览和缩略图，以及白名单字段。它不会把整份论文、来源代码、原始数据或整个条目自动复制出去。`include_in_public_catalog: false` 只控制导出，不会保护已经提交到公开 Git 仓库的文件；包含未公开研究材料或第三方参考原件的主仓库适合先设为私有。

## 8. 首版的边界与后续扩展

现在不抽象全局“万能主题”。不同图的布局与科学编码差异很大，森林图的区间与对数轴、时序图的共享坐标、复合图的面板比例，无法靠一套颜色和字号充分表达。先在单条目中积累真实可用的配置；当多份配方反复出现相同需求时，再提取小范围公共组件。

本仓库不包含 Skill 或自动检索模型。v0.3.0 的网页（见 [网页使用、发布与扩展](website.md)）沿着稳定的条目数据提供浏览、筛选、详情、调色实验、拼板和复制指令，不改写已经验收的绘图脚本；网页本身不写仓库。新功能以独立前端模块加入，若遇到真实的维护问题，再增加对应能力。

随包示例用于验证导入、参数化绘图、对照、验收和新输入运行这些工程环节。参考图本身是自生成材料；示例通过不构成陌生论文截图复现能力或准确率的证据。实际重建的工作方法见 [高保真重建规约](reproduction-guide.md)，项目采用的外部技术来源集中在根目录的 [SOURCES.md](../SOURCES.md)。
